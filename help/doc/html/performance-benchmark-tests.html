Performance Benchmark Tests

Script Looping
This test is an empty For/Next loop.

The Iterations value is the upper limit of the loop. This type of operation shows significant performance improvement with machine-code compilation. Expect around a 2000% increase.

TAK Benchmark
The TAK benchmark is a variant of a benchmark originated by researcher Ikuo Takeuchi, and is widely used to compare programming tools that make extensive use of function calls. The commonly used TAK benchmark algorithm is a variant originated when John McCarthy of Stanford University recalled the original Takeuchi function incorrectly at the start of a benchmarking effort. TAK uses a recursive function that when called with the initial values of 18, 12, and 6, puts the processor through 63,609 function calls and 47,706 subtractions by 1. The Iterations value is the number of times to perform the call, passing 18, 12, and 6 each time. This type of operation shows significant performance improvement with machine-code compilation. Expect around a 2000% increase.
Array Sorting
This test uses a bubble-sort algorithm to sort an array of integers. The Items value is the size of the array. The items are initially sorted in reverse order to achieve a worst-case sort. This type of operation shows a measurable performance improvement with machine-code compilation. Expect around a 500% increase.
Global Function Overhead
This test calls an empty global function Iterations times, and measures the overhead penalty associated with global functions. Function overhead is one of the areas of greatest performance improvement with machine-code compilation. However, the improvement for global functions are not as great as for object functions. Expect around a 1000% increase.
Object Function Overhead
This test calls an empty window function Iterations times. This measures the overhead penalty associated with object functions. Function overhead is one of the areas of greatest performance improvement with machine-code compilation. Expect close to a 3000% increase.
Event Overhead
This test calls an empty window event Iterations times. This measures the overhead penalty associated with events. There is no difference between object functions and events. Expect results similar to the Object Function Overhead test, close to a 3000% increase.
Window Instantiation
This test opens a window with no controls on it Iterations times. This measures the overhead associated with instantiating windows. This is one area where machine-code compilation has no effect. Opening windows and instantiating controls is the same for both types of executables.
String Parsing
This test performs a global change on a string. This includes using the Pos() function to find the old text, and the Left() and Right() functions, together with string concatenation, to make the change. The Iterations value is the number of times to perform the global change. This type of operation relies on built-in PowerBuilder functions which are already machine-code compiled. Therefore, you should expect little difference.
Global Variable
This test uses a global variable in a simple integer addition statement. This measures the overhead associated with global variables. The Iterations value is the number of times to execute the statement. Global variable overhead is reduced measurably with machine-code compilation. Expect around a 500% increase.
Global Constant
This test uses a global constant in a simple integer addition statement. This measures the overhead associated with constants. The Iterations value is the number of times to execute the statement. Global constant overhead is reduced significantly with machine-code compilation. Expect close to a 3000% increase. Also notice that using constants instead of variables results in much greater performance with a machine-code executables than with p-code.
Using DataStores
This test copies all rows from a DataStore into variables using the appropriate GetItem function then writes them to another DataStore using SetItem. The DataWindow used contains data from the sales_order table which has 6 columns and over 600 rows. The Iterations value is the number of times to perform the copy. This type of operation shows a small performance improvement with machine-code compilation. Expect around a 50% increase.
